How every packet was built (keep doing this):
1. **One branch per packet:** `pkt/V1-<ID>`, stacked on its chain's previous packet, or on the integration head.
2. **Tests first.**
   - Commit the failing tests alone; the message records the RED run: command, counts, and why each fails.
   - Then commit the fix.
   - Server changes are proven on a real Postgres database through the HTTP routes. Web screens get vitest + testing-library tests.
3. **Release 0 must stay MET** (`pnpm --filter server proof:release0`).
   - A required Release 0 case or manifest may change only where the plan's `r0_register` row says AMEND under an approved owner ruling, and exactly as ruled.
   - Never weaken, skip or quarantine a test.
4. **New test fixtures use a registered prefix** (`^[kv]NN[a-z]_$`) in `apps/server/test/helpers/fixture-prefixes.json`; `fixture-prefix-registry.spec.ts` enforces it.
   - When two branches both add prefixes, the merge conflict in that file is a union of both sides' entries.
5. **No other changes:** no new dependencies, no schema changes or migrations unless the packet is a migration packet, no real provider traffic, no production access.
6. **Two reviews, then a repair.** Each packet gets a security-tenancy review and a correctness-regression review.
   - Blocking and major findings are repaired, tests first.
   - Minor ones are repaired when small; otherwise they are recorded.
7. **Scan before every push:**
   - secret shapes;
   - provider key formats;
   - password literals and `user:pass@` URLs.

   Test secrets are built at run time from fragments, never written as literals. CI service databases use `POSTGRES_HOST_AUTH_METHOD: trust`, never a password literal.
8. **One PR per wave, then merge.** Finished packets merge into an integration branch (`--no-ff`). The integration head gets a full check: every suite, both typechecks, lint, run-manifests and proof:release0. Then one PR per wave goes to main, merged with a merge commit when CI is green.

## 5. Run and verify locally

Requirements: Node 22, pnpm 9, Postgres 16 with pgvector, Redis. `docker-compose.yml` starts `db` and `redis`.

```bash
pnpm install --frozen-lockfile
```

```bash
pnpm test:local
```

`pnpm test:local` (`scripts/test-local.sh`) is the one-command run. It admits only local resources, starts db and redis, generates the Prisma client, builds the workspace packages, applies migrations, builds the server and runs the Release 0 suites. Its header lists the options, including running other suites.

Step by step, against a local database:

```bash
pnpm --filter @keyflow/shared --filter @keyflow/db --filter @keyflow/api build
```

```bash
pnpm --filter server build
```

```bash
cd apps/server && npx vitest run
```

```bash
cd apps/web && npx vitest run
```

```bash
cd apps/server && NODE_OPTIONS=--max-old-space-size=6144 npx tsc --noEmit
```

```bash
cd apps/web && npx next typegen && npx tsc --noEmit
```

```bash
pnpm --filter server lint --max-warnings 3343
```

```bash
pnpm --filter web lint --max-warnings 26
```

```bash
node scripts/proof-admission/run-manifests.mjs --skip-build
```

```bash
pnpm --filter server proof:release0 -- --skip-build
```

Notes:
- Server tests need `DATABASE_URL`, `DIRECT_URL` and `REDIS_URL` pointing at local services, plus `NODE_ENV=test`. Integration suites create their own fixtures under their registered prefix.
- Build the ICU test database with `CREATE DATABASE <name> TEMPLATE template0 LOCALE_PROVIDER icu ICU_LOCALE 'en-US' LOCALE 'C.UTF-8'`, then apply migrations, so collation matches CI.
- Server `tsc` needs about 6 GB of heap.
- On a loaded machine some suites time out at 5 s, and proof reports go stale after 600 s (`KF_PROOF_REPORT_STALE`). Re-run those suites alone before treating them as failures.
- Web `tsc` needs `next typegen` first, because `next-env.d.ts` is generated and git-ignored.
