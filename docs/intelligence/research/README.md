# KEYFLOWOS Research & Development Corpus

Status: ACTIVE RESEARCH PROGRAMME
Authority: RESEARCH ONLY unless promoted by the canonical architecture-forensics process.

## Purpose

This area preserves cross-disciplinary R&D used to pressure-test KEYFLOWOS and KEY. It is intentionally separate from accepted architecture.

Research sources may include books, papers, standards, external systems, incident reports, repositories, and domain literature.

Nothing here becomes canonical architecture merely because it is famous, persuasive, recent, or repeatedly cited.

## Required transformation

SOURCE CLAIM -> PRINCIPLE -> MODERN EVIDENCE / INTERPRETATION -> AI-AGENT / KEY EQUIVALENT -> CURRENT KEYFLOWOS REALITY -> GAP -> ANTI-DUPLICATION CHECK -> CANDIDATE CHANGE -> PRESSURE TEST -> ADOPT / REJECT / DEFER

Accepted architecture still follows the normal programme method:
MAP -> MICROSCOPIC TRACE -> JOURNEY -> CONSTELLATION -> KERNEL -> DYNAMIC / CAUSAL / FEEDBACK GRAPH -> FINDING -> CONTRADICTION -> ANTI-DUPLICATION CHECK -> STANDARDS / FRONTIER PRESSURE TEST -> TARGET CONTRACT / RECOMMENDATION -> BACKWARD RE-AUDIT -> CONVERGENCE.

## Research states

- QUEUED: source identified but not dissected.
- EXTRACTING: chapter/section claims are being captured.
- TRANSLATED: KEY / KEYFLOWOS equivalents mapped.
- REPO_PRESSURE_TESTED: compared against live repository reality.
- CROSS_LENS_TESTED: tested against other disciplines/sources.
- CANDIDATE: warrants normal architecture-forensics treatment.
- ADOPTED: promoted through canonical architecture process.
- REJECTED: explicitly not adopted.
- DEFERRED: potentially useful but not justified now.
- SUPERSEDED: replaced by stronger later evidence.

## Durable rule

Preserve source -> interpretation -> candidate decision separately.

Never silently convert a book claim into a fact, a metaphor into architecture, AI inference into authoritative truth, an attractive abstraction into a runtime, or a summary into implementation scope.
