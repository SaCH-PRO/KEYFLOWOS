## 3. Correction churn reveals missing pre-edit proof dimensions

Several correction classes are visible in history:

### Shape/type correctness
Examples:
- wrong structural type in checkpoint containers;
- non-string packet/branch identities;
- hold mapping shape.

### Identity correctness
Examples:
- exact artifact binding;
- packet-id semantics;
- mapping keys such as __proto__, constructor and colon-bearing identifiers.

### Parser/codec correctness
Examples:
- malformed repeated fields;
- YAML key/value round-trip;
- column-0 envelope parsing.

### Recovery correctness
Examples:
- malformed authority stops fold;
- reviewed re-anchor;
- obsolete anchor controls.

### Proof correctness
Examples:
- vacuous negative control after code movement;
- exact-head proof/artifact lineage;
- skipped runner test distinction.

### Operator/rendering correctness
Examples:
- invalid hold container rendered misleadingly despite drift.

These categories can become reusable pre-edit/adversarial checklists rather than being rediscovered in review.

## 7. A behavioral hotspot needs multiple dimensions

Proposed hotspot score should eventually combine:

- change frequency;
- correction frequency;
- number of review findings;
- number of distinct semantic owners touched;
- temporal coupling with other files;
- negative-control additions/repairs;
- CI failure recurrence;
- branch divergence/rebase friction;
- production/business risk;
- authority/state/effect criticality;
- context reconstruction cost.

Do not rank solely by lines changed.
