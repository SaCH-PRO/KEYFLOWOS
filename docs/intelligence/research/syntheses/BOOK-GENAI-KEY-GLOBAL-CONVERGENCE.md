## 3. Evidence posture

Sources are separated into:

- SOFTWARE / SYSTEMS ENGINEERING — design, testing, distributed systems, architecture evolution.
- COGNITIVE / HUMAN FACTORS — cognition, interface design, judgment, team environment.
- FORMAL / COMPUTATIONAL — interpreters, abstraction, search, decision procedures.
- PHILOSOPHICAL / METAPHORICAL — useful for hypothesis generation only unless independently supported.
- CONTESTED EMPIRICAL — must be replication-aware before technical adoption.

Important caution: psychology findings are not promoted into KEY mechanisms merely because they appear in a respected book. Large replication programmes have shown substantial non-replication and effect-size shrinkage in social/behavioral science. Therefore behavioral claims are used as design hypotheses unless they have stronger support.

## 4. Cross-source convergence laws

### LAW B1 — More context is not more intelligence

Primary lenses:
- Felienne Hermans, *The Programmer's Brain*
- Don Norman, *The Design of Everyday Things*
- GenAI Layers 4, 5, 7, 9

Distinguish at least:

- KNOWLEDGE_ABSENT
- RETRIEVAL_FAILURE
- CONTEXT_OVERLOAD
- REPRESENTATION_FAILURE
- REASONING_FAILURE

These are different failures and require different corrections.

Implication:
Context Genome / Context Compiler should maximize decision-relevant information while preserving provenance, authority, freshness, unresolved conflict, and explicit exclusions.

Do not respond to every failure by increasing token volume.

### LAW B2 — Shared artifacts outrank agent identity

Primary lenses:
- Weinberg, *The Psychology of Computer Programming*
- Brooks, *The Mythical Man-Month*
- Peopleware
- GenAI Layer 3 and Layer 9

ChatGPT, Claude Code, Kimi Code, or any later agent may disagree. The system must resolve work through shared repository evidence, explicit authority, exact revision, and proof rather than social confidence or model identity.

This strengthens:
- one canonical owner per concern;
- exact-head evidence;
- durable task context;
- independent semantic review;
- no private architectural truth.

### LAW B3 — Hide mechanism, not truth

Primary lenses:
- Ousterhout, *A Philosophy of Software Design*
- SICP
- The Practice of Programming
- GenAI Layers 3, 7, 8

Prefer deep semantic modules: a small stable interface can contain substantial necessary mechanism.

But KEYFLOWOS adds a stronger condition:

> HIDE MECHANISM, NOT AUTHORITY, EFFECTS, FAILURE, RECOVERY OR EVIDENCE.

A module is not "deep" if callers cannot tell whether it can mutate state, requires approval, may fail ambiguously, or what evidence proves completion.

### LAW B4 — Representation is a tool, not truth

Primary lenses:
- SICP
- DDIA
- Hermans
- GenAI Layers 4 and 5

Embeddings, vectors, graphs, summaries, prompts, traces and compiled context are representations over underlying state.

They may accelerate reasoning but may not silently become canonical business truth.

This reinforces:
- pgvector as rebuildable projection;
- ContextBundle as projection;
- observability as projection;
- model output as proposal/evidence candidate;
- semantic similarity as retrieval evidence, never authority.

### LAW B5 — Time and state are first-class semantics

Primary lenses:
- SICP: state, concurrency, streams, different computational models of time.
- DDIA: ordering, retries, consistency, replication, fault tolerance.
- GenAI Context Genome and capability/effect work.

Every important KEY claim/action should distinguish where relevant:

- valid time;
- recorded time;
- revision;
- supersession;
- causation/correlation lineage;
- pending/unknown external outcome;
- retry/replay identity.

A timeless "memory fact" or "action success" is often semantically incomplete.

### LAW B6 — Fast vs deliberate cognition is a routing problem, not a personality claim

Primary lenses:
- *Thinking, Fast and Slow*, used replication-aware
- Algorithms to Live By
- GenAI Layers 1, 3, 9
- existing KEY fast-path / deep-think code

KEY should not imitate a literal human System 1/System 2 model.

Instead define computational modes:

- FAST: low-risk, familiar, well-specified, cheap, reversible.
- DELIBERATIVE: uncertainty, conflict, novelty, materiality, high-risk effects, long horizon, multi-step planning.
- ESCALATE: insufficient evidence, unresolved authority, unacceptable uncertainty.

Routing should be driven by measurable task/risk features and evaluation, not anthropomorphic labels.

### LAW B7 — Actionability requires discoverability and feedback

Primary lenses:
- Don Norman
- GenAI Layers 7, 8, 10

For consequential KEY actions, the operator-facing projection should make clear:

1. what KEY observed;
2. what KEY believes/inferred;
3. what KEY proposes;
4. what authority is required;
5. what will change;
6. what actually happened;
7. what can be undone/reconciled.

This is a projection over existing proposal/verdict/effect/evidence owners, not a new authority system.

### LAW B8 — Coordination cost is a real systems cost

Primary lenses:
- Brooks
- Peopleware
- Weinberg
- Development Organism

More agents do not imply linear throughput.

Parallelism is valuable only when work is:
- semantically separable;
- owner-separated;
- write-set compatible;
- independently verifiable;
- merge/reconciliation bounded.

Measure:
- handoffs;
- repeated context reconstruction;
- branch collisions;
- duplicated research;
- review-cycle count;
- rework after stale authority.

### LAW B9 — Repository history is architectural evidence

Primary lens:
- Adam Tornhill, *Software Design X-Rays*

Static dependency graphs tell what code can depend on. Version history tells what repeatedly changes together and where organizational/technical coupling actually occurs.

Use history to surface:
- hotspots;
- temporal coupling;
- ownership concentration;
- repeatedly co-changing modules;
- high-churn low-test areas.

Historical coupling is evidence for investigation, not automatic architecture authority.

### LAW B10 — Green tests are evidence only if sensitive to the claimed defect

Primary lenses:
- Beck, TDD
- Fowler, Refactoring
- The Practice of Programming
- GenAI Layer 9 / Assurance

Use:
- focused tests for rapid feedback;
- characterization before legacy refactors;
- integration/real-database tests for persistence semantics;
- mutation/negative controls for critical invariants;
- exact-head broad CI for admission.

A test suite that remains green when the claimed defect is restored is not proof of that invariant.

### LAW B11 — Simplicity is semantic compression, not line-count minimization

Primary lenses:
- Ousterhout
- SICP
- Clean Code, treated as heuristic
- Brooks

Measure simplicity through:
- source-of-truth count;
- semantic owner count;
- required concepts per caller;
- hidden coupling;
- state-transition count;
- failure-mode count;
- operational dependencies;
- change blast radius.

Short functions/classes are not universally simpler. Clean Code prescriptions remain context-dependent and are pressure-tested against Ousterhout and repository evidence.

### LAW B12 — Learning cannot self-promote

Primary lenses:
- Algorithms to Live By
- GenAI Layers 6 and 9
- KEY governed learning

Exploration/exploitation, adaptive routing, learned procedures, model fine-tuning and policy updates may propose candidates.

They may not self-authorize deployment.

Promotion requires admitted evidence, explicit scope, rollback/retirement, and authority.

## 9. Convergence result

The book corpus does not overturn the GenAI global convergence.

It sharpens it into a stronger operating law:

> KEY should be a provenance-aware, authority-bounded cognitive system that compiles the smallest sufficient context, selects an appropriate reasoning mode, exposes understandable action semantics, executes through one governed capability/effect substrate, verifies reality independently of model confidence, and learns only through admitted evidence.

That result is mature enough to derive bounded implementation packets.
