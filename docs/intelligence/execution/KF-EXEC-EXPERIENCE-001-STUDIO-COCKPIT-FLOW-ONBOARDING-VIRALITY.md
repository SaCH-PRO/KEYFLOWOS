## Objective
Make the original KeyFlow experience explicit: users build/configure in Studio and run the business from Cockpit through KEY, Flow Feed and Flow Graph, with outcome-first onboarding and tasteful product/creator/network virality loops.

## Locked invariants
1. Cockpit is projection/control surface, not source of truth.
2. Flow Feed entries link to canonical evidence/source state.
3. Flow Graph visualizes flows/bottlenecks; it does not invent state.
4. KEY command resolves to exact capabilities/governance.
5. Studio configuration cannot bypass authority/domain invariants.
6. onboarding optimizes time-to-value without creating invalid default authority.
7. gamification is evidence-based and cannot corrupt Index/financial truth.
8. Powered-by-KeyFlow and referral/marketplace growth are clearly product attribution, not hidden ranking manipulation.
9. frontend never displays stronger state than canonical source.
10. degraded/missing source is distinguishable from zero/healthy.
