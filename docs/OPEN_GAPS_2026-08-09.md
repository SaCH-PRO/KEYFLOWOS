# Open gaps, 2026-08-09

Written at the end of the week that closed the fork, fixed the boot, armed CI and
deployed. Everything here is either measured or explicitly marked as unverified.

Ordered by whether it can hurt someone today, not by effort.

---

## 1. Service worker caches are versioned by hand

`apps/web/public/sw.js` names its caches `kf-shell-v3`, `kf-static-v3`,
`kf-api-v3`. Nothing in the build or deploy bumps those strings. Combined with
`skipWaiting()` and `clients.claim()`, a returning user keeps yesterday's
JavaScript against today's API — indefinitely — until they clear site data.

This is probably what made the 2026-08-09 sign-in fail: clearing storage fixed
it, and the worker does `cacheFirst(request, STATIC_CACHE)` for same-origin
assets.

**Not** the POST-queue path at `sw.js:220`. That was the first diagnosis and it
was wrong: the queue only fires from `fetch(request).catch(...)`, and line 218
skips cross-origin requests — the API is `api.keyflowos.com` while the app is
`keyflowos.com`, so the worker never sees a login POST at all.

*Fix:* derive the cache name from `GIT_COMMIT`, which the Dockerfile already
passes as a build arg and `/healthz` already reports. Needs someone to check how
`sw.js` is served and whether build-time substitution reaches it.

## 2. `.env.production` exists only on the box

No template, no checked-in manifest of required variables. Rebuild the VPS and
you rediscover every secret by watching things fail — which is the exact failure
the missing-OpenAI-key fix was written for. An env manifest listing names (not
values) is about an hour.

## 3. One app instance only

28 `@Cron` jobs, no leader election or single-runner guard. Two replicas means
two morning briefs, two weekly digests, and hormone state that shifts with
replica count rather than with the business. Latent while one instance runs.

## Known defects, unfixed

**`cron-scheduler`** — the last unmeasured instance of the Redis class
(`cron-scheduler.service.ts:14` → `queue.service.ts:116`). A probe against a dead
Redis did not hang, but the probe itself threw, so that is weak evidence. Needs a
proper measurement: real BullMQ queue, dead Redis, rejection handled, assert
`getRepeatableJobs()` settles.

**Two interfaces named `FullBusinessContext`** — `key-cortex-connector.types.ts:220`
and `key-cortex-context-v2.service.ts:221`. This is what hid the duplication
between `key-cortex-context-assembly.service.ts` (315 lines, zero casts, works)
and `key-cortex-context-v2.service.ts` (1,557 lines, every getter broken until
today). Both implement `getFullContext`; 16 callers use V2, and
`connector.service.ts:176` routes to assembly. Decide whether both should exist.

**`Promise.allSettled` in `getFullContext`** still swallows rejections. The new
real-database test catches it; the mechanism is unchanged.

**`/keystore/admin/*`** — any *member* of a business can manage listings and mark
orders delivered. Not a tenant breach: `BusinessGuard` correctly scopes to the
`businessId` in params/body/query and rejects a foreign one. It is role
granularity on a controller named `admin`.

**11 dead listeners** — `crm.deal.won` sharpest: won deals keep receiving nurture
sequences. Seven `key.*` are dead on both ends.

**`/app/document-intelligence`** — fabricated screen, two KEY tools name it as
their manual equivalent. Deleting it drops `check-tool-routes` off 245/245 unless
those tools are repointed or retired.

**8 doorless screens**, four of them `continental-ops/*` needing a parent page.

**6 lint errors** — five `react-hooks/set-state-in-effect` (inventory 62/91,
store customers 132, orders 258, promos 212), one in core-channels-section 163.
The Lint job is deliberately non-gating, so these block nothing; they keep the
board red, which is its own cost.

## Decisions, not defects

**68 `forwardRef`s** — accept the circular design or break it. Cycles enumerate in
seconds and the boot gate falsifies an attempt in about five, which is the rare
part. Note that removing six unused injections from `context-v2` on 2026-08-09
retired six edges at no cost; there may be more of those.

**Node 20.19+** — dissolves the entire class of "ESM-only dependency cannot be
required". `jose` came one lockfile edit from shipping an unbootable server, and
`uuid@14` already did it once. Also the prerequisite for the next item.

**Prisma 7** — blocked until someone checks whether `@prisma/client@7` ships a
`require` condition in its `exports`. If it is ESM-only, Node must move first.
The `url`-into-`prisma.config.ts` move is mechanical; the risk is migrate and
client runtime, against a `_prisma_migrations` history that was reconciled by
hand on 2026-08-09.

**Seven unassessed remote branches** — nobody has checked whether they are live
work or abandoned lines.

## The gap under the gaps

Every defect above was found by *running* something, never by reading. The
recurring shape, seven instances this week:

| Instance | What ran, and meant nothing |
|---|---|
| ModelGatewayService | a constructor that threw, taking every route with it |
| 47 `as any` casts | queries against a schema that does not exist |
| mocked AI gateway | a real constructor no test ever executed |
| `Promise.allSettled` | eight rejections turned into empty slices |
| ioredis offline queue | a command that never settled, so a documented guard never ran |
| `undefined >= 5` | a limit check whose value was silently undefined |
| a fabricated 200 | a response meaning "I did nothing", indistinguishable from success |

Four fixtures have been found asserting shapes the client cannot produce — a
`MediaAsset` with a nested `visualIntake` being the clearest. **A mock that
describes an impossible shape is worse than no test: it certifies the broken
thing as correct.**

The structural fix, if one thing gets built: a gate that flags Prisma fixtures
whose shape the schema cannot produce. That is the class, and it is mechanically
checkable — the same way `cast-call-integrity` made "a call to a method that does
not exist" checkable.
