# KeyFlow UI/UX Overhaul Blueprint

## 1. Core redesign objective

Transform the product from a **feature-rich application** into a **clear operating system** by reorganizing the interface around:

* operational awareness
* focused execution
* guided configuration
* premium public presence

The redesign should preserve all current and planned functionality, while improving:

* discoverability
* cognitive clarity
* visual consistency
* navigation flow
* system identity
* action speed
* perceived intelligence

---

# 2. Redesign doctrine

These are the non-negotiable rules.

## Rule 1: No feature removal

All redesign decisions must preserve:

* modules
* workflows
* advanced tools
* controls
* data visibility
* admin depth

## Rule 2: Prioritize by frequency, not by existence

The UI should not treat all functionality equally.
Common actions get priority.
Advanced actions remain accessible through layered disclosure.

## Rule 3: Separate “run” from “build”

Users should always know whether they are:

* operating the business
  or
* configuring the system

## Rule 4: One object, one home

Related functions around one entity should be unified into a single workspace.

## Rule 5: Design around state and action

Each screen must answer:

* What is happening?
* What matters?
* What needs action?
* What can I do now?

---

# 3. New product architecture

The entire app should be reorganized into **4 master surfaces**.

## A. Cockpit

Purpose: run the business in real time.

This is the default landing environment after login.

Contains:

* activity flow
* urgent tasks
* approvals
* key operational metrics
* system alerts
* recommendations
* AI command layer

This is not a dashboard in the generic sense.
It is the business pulse layer.

---

Purpose: perform deep work inside operational domains.

Contains:

* Clients
* Calendar
* Revenue
* Content
* Messages
* Flows

Each workspace should support deep management without fragmenting related actions across too many pages.

---

## C. Studio

Purpose: build, configure, and optimize the system.

Contains:

* Business setup
* Services and offers
* Playbooks / automations
* Team and permissions
* Branding
* Integrations
* Templates

Studio replaces generic “Settings.”

---

## D. Public

Purpose: manage outward-facing customer experiences.

Contains:

* Booking pages
* Payment pages

* shareable assets

Public should look more premium and emotionally polished than the internal app.

# 6. Global layout rules

## Grid

Use a consistent 12-column layout for desktop.
Do not let pages invent their own widths casually.

## Width behavior

* main content max width should be controlled
* wide data views can break wider, but still within system rules
* forms should not span too wide

## Side panel behavior

Right-side panels should be collapsible, persistent when useful, and reusable across workspaces.

## Density

Adopt a “comfortable-compact” density:

* enough space to feel premium
* tight enough to feel operational

Avoid both extremes:

* over-airy = slow and wasteful
* over-dense = stressful and cheap-feeling

# 13. Visibility and disclosure rules

These rules preserve functionality without clutter.

## Always visible

* current state
* primary actions
* key metrics
* immediate next step
* search/command
* filters relevant to task

## Conditionally visible

* secondary actions
* related records
* history
* recommendations
* previews

## Hidden behind expansion

* technical metadata
* advanced options
* logs
* raw settings
* rarely used controls
* power-user utilities

This must be system-wide, not screen-by-screen improvisation.

---

# 14. Visual design direction

## Design personality

The app should communicate:

* calm intelligence
* modern control
* operational confidence
* premium simplicity
* hidden depth

## Recommended style language

* deep neutral or graphite base
* selective high-contrast surfaces
* restrained accents
* minimal but purposeful gradients
* strong typography hierarchy
* subtle state colors
* tonal layering instead of too many borders

## Avoid

* overly playful SaaS visuals
* too many equal cards
* neon overload
* excessive glassmorphism
* heavy border grids
* noisy shadows
* oversized empty whitespace

---

# 15. Motion blueprint

Use motion sparingly and meaningfully.

## Good motion use

* panel expansion
* detail selection transitions
* command open/close
* feed updates
* drag/reorder in builders
* chart/graph state shifts
* success confirmation

## Avoid

* decorative motion on every hover
* delayed page loads
* dramatic bounces
* transitions that slow operations

Motion should communicate intelligence, not spectacle.

---

# 16. Empty state blueprint

Every empty state should do 4 things:

* explain the purpose of the area
* explain why it matters

Actions:

* Start from template

* View examples

This converts blankness into activation.
