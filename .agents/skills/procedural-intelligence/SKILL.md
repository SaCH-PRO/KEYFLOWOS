# Procedural Intelligence

Apply this workflow to recurring or high-information KEYFLOWOS work.

## 1. Recover reality

Before abstraction:
1. load canonical project/context state;
2. identify the exact episode(s), actors, subject, evidence, authority, constraints, outcome and unresolved contradictions;
3. distinguish observed facts from interpretation and hypothesis;
4. preserve exact provenance.

Do not learn a procedure from an inaccurately reconstructed episode.

## 2. Dissect the episode

Map context, trigger, actors, semantic subject, evidence, authority, constraints, execution, outcome, contradiction/recovery and learning opportunity.

Keep semantic, control, evidence, authority, execution, outcome and learning planes separate.

## 3. Detect reusable structure

Classify candidate structure as one-off episode, repeated pattern, protocol, procedure candidate, reusable operator, specialist phenotype, stable tissue/team or scale-unit candidate.

Prefer small composable chunks over giant macros.

## 4. Compile a ProcedureSpec candidate

Use docs/architecture/key-cognition/procedure-spec.v0.schema.json.

A candidate must declare applicability/initiation, context/freshness, capabilities, governance/risk/autonomy, ordered steps, evidence/provenance, invariants, retries/timeouts, stop/escalation, recovery/compensation, terminal outcomes, evaluator/negative controls and lineage.

Learned procedure != permission.

## 5. Specialize only when useful

For agent differentiation, derive the smallest phenotype from goal + context + scope + risk + authority + resource budget.

Bind only required procedures, tools, memory views and evaluators.

Do not create permanent named agents when an ephemeral specialist suffices.

## 6. Promote higher-order units carefully

Use docs/architecture/key-cognition/scale-unit.v0.schema.json.

A subsystem may become a higher-order unit only when it has stable identity/boundary, macro-state, observability, bounded actuation, authority boundary, invariants, resource budget, health/failure modes, drill-down provenance and peer/parent composition contract.

Compress complexity without destroying the route back to evidence.

## 7. Evaluate before autonomy

Follow: EPISODE -> CANDIDATE_PATTERN -> PROTOCOL -> PROCEDURE_SPEC -> EXECUTABLE -> SHADOW -> EVALUATED -> BOUNDED_AUTONOMY -> PROMOTED | QUARANTINED | RETIRED.

Use historical replay, shadow comparison, negative controls, failure injection and ablation. Do not activate a candidate because it is repeated, elegant or plausible.

## 8. Apply the non-negotiable laws

- procedure != permission;
- evidence != authority;
- spec != performance;
- association/repetition != verification;
- subject != attestation;
- timing/order are part of correctness;
- contradiction is a legitimate state;
- stop-on-abnormality is healthy behavior;
- recovery repairs the minimum violated relationship;
- routing preference never changes truth/authority;
- autonomy is staged and revocable;
- no hidden chat context may be required.

## 9. Persist the learning

For material discoveries:
- update issue #106 or the active procedural-intelligence packet;
- create/update canonical intelligence artifacts;
- preserve rejected/superseded ideas with rationale;
- link the episode, procedure version, experiment evidence and outcome;
- do not claim runtime implementation unless a live causal path is proven.
